# MASAR-ERP

نظام تخطيط موارد ومحاسبة متعدد الشركات، مبني كتطبيق مخصص فوق **Frappe Framework وERPNext** بدلاً من إعادة اختراع دفتر الأستاذ والمخزون والمبيعات من الصفر.

> الحالة الحالية: بدأ التنفيذ البرمجي. تمت إضافة واجهات API أولية لقراءة شجرة حسابات ERPNext وإنشاء حساب فرعي عبر DocType القياسي، مع فحوصات صلاحيات الشركة والحساب الأب. لم يتم بعد تشغيلها على موقع Frappe/ERPNext فعلي أو اختبار ترحيل محاسبي حقيقي أو نشر إنتاجي؛ لذلك لا يُعد النظام جاهزاً للاستخدام المالي بعد.

## الرؤية
- محاسبة مالية متكاملة ودليل حسابات هرمي وقيود يومية ودفتر أستاذ.
- توجيه محاسبي للمبيعات والمشتريات والمخزون والأصول والرواتب والمصروفات.
- خزائن متعددة وبنوك وشيكات وتقارير تفصيلية ومجمعة.
- عملاء رئيسيون وفروع مع تتبع المديونيات منفردة ومجمعة.
- شركات وفروع ومراكز تكلفة وصلاحيات دقيقة.
- عملاء وموردون ومبيعات ومشتريات ومخزون.
- تقارير مالية وإدارية قابلة للتدقيق.
- تهيئة محلية لمصر ومواءمة مع EAS وIFRS بعد المراجعة المحاسبية والتحقق.
- واجهة عربية RTL وتجربة مناسبة للهاتف والحاسوب.
- تشغيل متدرج دون اتصال: مسودات محلية آمنة ومزامنة خادمية تمنع التكرار والتعارض، دون ترحيل محاسبي نهائي من الجهاز.

## التنفيذ الحالي
- `masar_erp/accounting.py`: واجهات قراءة شجرة الحسابات وإنشاء حساب فرعي وقراءة توجيهات الحسابات باستخدام ERPNext القياسي، مع التحقق من تسجيل الدخول وصلاحية الشركة والحساب الأب.
- `MASAR Account Mapping`: DocType لتوجيه الحسابات حسب الشركة ونوع العملية ومركز التكلفة، مع منع الحسابات التجميعية أو المعطلة أو التابعة لشركة أخرى.
- `masar_erp/masar_erp/page/masar_dashboard`: لوحة تحكم عربية متجاوبة مرتبطة بدفتر الأستاذ العام، وفواتير المبيعات والمشتريات المرحلة، والقيود اليومية، وكميات المخزون. تعرض إجمالي مبيعات ومشتريات الشهر الحالي والذمم المفتوحة، مع روابط مباشرة إلى المستندات، وفق صلاحيات المستخدم. لا تعرض أرقامًا افتراضية.
- `masar_erp/tests/test_accounting_contract.py` و`test_dashboard_contract.py`: فحوصات عقدية ثابتة لواجهات الحسابات واللوحة والصلاحيات ومصادر البيانات.
- فحص GitHub Actions يتضمن ترجمة Python واختبارات pytest وفحص صياغة JavaScript.
- هذه الفحوصات لا تعادل بعد اختبارات تكامل على قاعدة بيانات Frappe حقيقية.

## القرار التقني
- **Frappe Framework / ERPNext**: محرك ERP والمحاسبة الأساسي.
- **Python**: منطق التطبيق المخصص.
- **MariaDB وRedis**: خدمات البنية التي يعتمد عليها Frappe.
- **JavaScript**: واجهات Frappe والتفاعلات.
- **GitHub Actions**: فحوصات الجودة الآلية الأولية.

لن ننسخ شفرة ERPNext أو نعيد بناء وظائفه الأساسية دون داعٍ؛ سنضيف تطبيق MASAR المخصص وتهيئات مصرية موثقة.

## التطوير المحلي
يتطلب تشغيل التطبيق بيئة Frappe/ERPNext متوافقة. يجب تثبيت التطبيق على موقع تجريبي، ثم تنفيذ `bench migrate` واختبارات التكامل قبل استخدام الواجهات. راجع دليل المعمارية وخارطة الطريق.

## مبادئ العمل
1. لا بيانات تجريبية توهم بأنها بيانات حقيقية.
2. لا أسعار أو نسب ضرائب أو قواعد امتثال غير موثقة.
3. فصل بيانات الشركات والصلاحيات واختبارها.
4. حفظ أثر تدقيقي للعمليات المالية.
5. لا نشر إنتاجي قبل الاختبارات والنسخ الاحتياطي ومراجعة الأمن.
6. إبقاء المستودع القديم mohasaba مستقلاً دون تعديل.
7. عدم تخزين بيانات مالية خاصة في ذاكرة التخزين المؤقت العامة للمتصفح.
8. لا ترحيل محاسبي نهائي أثناء العمل دون اتصال.
9. دليل الحسابات والقيود والأستاذ العام في ERPNext هي مصدر الحقيقة، ولا ننشئ دفتر أستاذ موازياً.
10. لا يُعلن الامتثال لـ EAS أو IFRS أو متطلبات ETA دون اختبارات ومراجعة مختصين.
