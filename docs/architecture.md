# المعمارية التقنية

## المبدأ
MASAR-ERP تطبيق أعمال مخصص يعمل فوق Frappe وERPNext. ERPNext يوفر النواة المحاسبية والمخزون والمبيعات والمشتريات؛ ويضيف MASAR إعدادات وتجربة عربية وتدفقات محلية معتمدة.

## الطبقات
1. **منصة ERP**: Frappe Framework وERPNext، بإصدار ثابت ومتوافق يتم تثبيته في بيئة التشغيل.
2. **التطبيق المخصص**: الحزم والواجهات وDocTypes والتقارير الخاصة بـ MASAR.
3. **البيانات**: قاعدة بيانات MariaDB لكل موقع Frappe، مع نسخ احتياطية دورية واختبار الاستعادة.
4. **الخدمات المساندة**: Redis للمهام والذاكرة المؤقتة والاتصال الفوري.
5. **التكاملات**: واجهات موثقة ومفاتيح محفوظة في إعدادات الخادم، لا في المستودع أو المتصفح.

## حدود المحاسبة
- يجب أن تمر المعاملات المرحلة عبر آليات ERPNext القياسية ودفتر الأستاذ.
- لا نعدل أرصدة الأستاذ مباشرة ولا نحذف القيود المرحلة لتصحيح الأخطاء؛ تستخدم عمليات الإلغاء والعكس المسموح بها.
- أي تخصيص للضرائب أو الفاتورة الإلكترونية المصرية يحتاج مواصفات رسمية واختبارات قبول قبل تفعيله.
- العملة الافتراضية وإعدادات السنة المالية وشجرة الحسابات تُحدد لكل شركة ولا تُفترض عالمياً.

## الشركات والفروع
تُستخدم آليات Company وCost Center والصلاحيات القياسية في ERPNext. يجب اختبار منع تسرب البيانات بين الشركات، بما في ذلك التقارير وواجهات API والتصدير والمرفقات.

## الأمن
- أقل صلاحية لازمة لكل دور.
- عدم تخزين كلمات المرور أو مفاتيح API أو ملفات البيئة في Git.
- سجل تدقيق للعمليات الحساسة.
- حماية واجهات API والتحقق من صلاحية المستخدم والشركة على الخادم.
- نسخ احتياطية مشفرة وسياسة احتفاظ واختبار استعادة.
- مراجعة الاعتماديات والتحديثات الأمنية قبل كل إصدار.

## قرار النشر
لا يوجد إعداد إنتاج معتمد في هذه المرحلة. يجب تثبيت إصدارات Frappe وERPNext المتوافقة، واختبار الترقية والاستعادة، وتحديد استضافة تدعم خدمات الخلفية وقاعدة البيانات وRedis والمهام المجدولة. استضافة واجهة ثابتة وحدها لا تكفي لتشغيل ERPNext.
