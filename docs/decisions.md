# القرارات التقنية

## ADR-001: البناء كتطبيق Frappe مخصص
**الحالة:** معتمد مبدئياً.

نستخدم ERPNext للمحاسبة والمخزون والمبيعات والمشتريات، ونبني MASAR كتطبيق مخصص إضافي. هذا يقلل مخاطر إعادة تنفيذ دفتر الأستاذ ويتيح الاستفادة من مسارات ERP القياسية.

## ADR-002: عدم اعتبار GitHub Pages أو Vercel استضافة ERP
**الحالة:** معتمد.

ERPNext يحتاج خادم تطبيق وقاعدة بيانات MariaDB وRedis وعمال مهام وخدمات مجدولة. استضافة الواجهة الثابتة وحدها لا تشغله. يجب اختيار منصة تدعم هذه الخدمات أو استخدام إعداد Frappe Docker موثق.

## ADR-003: عدم افتراض الامتثال المصري
**الحالة:** معتمد.

لا نعلن توافقاً ضريبياً أو تكاملاً مع الفاتورة الإلكترونية حتى نراجع أحدث مواصفات الجهات الرسمية وننفذ اختبارات تكامل فعلية بمفاتيح بيئة الاختبار.

## ADR-004: فصل المستودعات
**الحالة:** معتمد.

مستودع MASAR-ERP مستقل. لا يتم تعديل مستودع mohasaba ضمن هذا العمل.
